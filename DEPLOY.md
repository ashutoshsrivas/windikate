# Windikate — free hosting recipe

Everything in this repo can be hosted on free tiers. Three services involved:

| What | Where | Cost |
|---|---|---|
| Static landing site (root of repo) | **Vercel** (or GitHub Pages) | $0, always free |
| Analysis-app frontend (Next.js) | **Vercel** | $0, always free |
| Analysis-app backend (Express)   | **Render** Web Service | $0, free tier sleeps after 15 min idle |
| MySQL database                    | **TiDB Cloud Serverless** | $0, 25 GB always free, MySQL-protocol compatible |

Total: **$0 / month**.

---

## 1 · Static landing site → Vercel

The repo root (`index.html`, `assets/`, all the other `.html` pages) is a plain static site.

1. Go to <https://vercel.com/new>, click **Import Git Repository**, choose `ashutoshsrivas/windikate`.
2. **Framework Preset**: _Other_.
3. **Root Directory**: leave as `./` (the repo root).
4. **Build Command**: leave blank.
5. **Output Directory**: leave as `./`.
6. Click **Deploy**.

Vercel reads the included `vercel.json` for cache headers + clean URLs and serves all `.html` files directly. First deploy takes ~30 seconds; from then on it auto-deploys on every push to `main`.

> Alternative: GitHub Pages. Settings → Pages → Source = `main` / root. Equally free, slightly slower CDN.

## 2 · Database → TiDB Cloud Serverless

TiDB Cloud Serverless speaks the MySQL protocol so `mysql2` works without changes.

1. Sign up at <https://tidbcloud.com> (free, no card required).
2. Create a **Serverless** cluster — pick `aws-us-east-1` or `aws-ap-south-1`.
3. After provisioning, click **Connect** and pick **General** → copy the host / port / user / password.
4. Apply the schema:
   ```bash
   mysql -h gateway01.<region>.prod.aws.tidbcloud.com \
         -P 4000 -u <prefix>.root -p \
         --ssl-mode=VERIFY_IDENTITY \
         < analysis-app/backend/db/schema.sql
   ```
5. Note the connection values — you'll paste them into Render in the next step.

> Alternatives if you prefer: **Aiven** (free MySQL trial, 30 days) or **FreeSQLDatabase.com** (very small, dev only).

## 3 · Express backend → Render

Render reads `render.yaml` at the repo root and provisions a free Web Service.

1. Go to <https://render.com/dashboard>, click **New** → **Blueprint**.
2. Connect the `ashutoshsrivas/windikate` repo.
3. Render detects `render.yaml` and creates `windikate-api`. It asks you to fill the secret env vars:

   | Variable | Value |
   |---|---|
   | `DB_HOST` | `gateway01.<region>.prod.aws.tidbcloud.com` |
   | `DB_PORT` | `4000` |
   | `DB_USER` | `<prefix>.root` |
   | `DB_PASSWORD` | _your TiDB password_ |
   | `ALLOWED_ORIGIN` | _your Vercel frontend URL, see step 4_ |

   `JWT_SECRET` is auto-generated by Render. `DB_NAME` defaults to `windikate_analysis`. `DB_SSL` is detected automatically because the host is remote.

4. Click **Apply**. Render installs deps and starts the service. The public URL looks like `https://windikate-api.onrender.com`. Hit `/api/health` to confirm.

> Free-tier note: Render sleeps the service after 15 min of inactivity. The first request after a sleep takes ~30 s while it cold-starts. Subsequent requests are fast. Fine for demos; not for production.

## 4 · Analysis-app frontend → Vercel (second project)

The Next.js app lives in `analysis-app/frontend/`. We deploy it as a **separate** Vercel project so it doesn't conflict with the static landing site.

1. <https://vercel.com/new> → **Import Git Repository** → `ashutoshsrivas/windikate` (again — this is a second project).
2. **Framework Preset**: _Next.js_.
3. **Root Directory**: `analysis-app/frontend`.
4. **Build Command**: leave default (`next build`).
5. **Environment Variables**:
   - `API_BASE_URL` = `https://windikate-api.onrender.com` (your Render URL)
6. Click **Deploy**. URL will be something like `https://windikate-analysis.vercel.app`.

7. Go back to your Render service → **Environment** → set `ALLOWED_ORIGIN` to the Vercel URL above and **Save changes**. Render will restart the API with the new CORS origin.

## Troubleshooting

**Backend boots but DB errors on first request.**
TiDB requires TLS — the pool enables it automatically when `DB_HOST` is not `127.0.0.1`. If you've set `DB_HOST=localhost` (instead of a remote hostname), the pool won't enable TLS. Set `DB_SSL=true` to force it.

**CORS errors in the browser.**
`ALLOWED_ORIGIN` on Render must exactly match the frontend origin (no trailing slash). After editing it on Render, the service auto-restarts in ~30 s.

**Render service shows "starting" forever.**
Check the build log. The common cause is `analysis-app/backend/.env` accidentally committed — it gets ignored if you push fresh after `.gitignore` was added.

**Free-tier sleep is killing the demo.**
A simple uptime ping (UptimeRobot, Better Uptime, cron-job.org) hitting `/api/health` every 10 minutes keeps it warm. Or upgrade Render to a paid plan ($7/mo).
